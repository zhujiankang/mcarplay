# 0.1.17：网络iAP2恢复、封面、语音建流与源端帧率

分支 `mercedes-carlife`，基于0.1.16代码及后续分析提交 `4f4a89f6f4c1becb77c1bd329a2cb26983de35e2`。本轮按用户要求依次实现四项修复；没有新增奔驰实车数据。此前21:17报告实际安装0.1.14，不能作为本版验收。

## 1. 网络iAP2：有界独立恢复与完成状态

- 网络虚拟链路DEAD后，清除网络认证/控制完成状态、旧订阅和待传封面。音视频、CarWith、事件及RTSP连接继续存活。
- 最多尝试两次独立重建：首次冷却5秒，后续距上次尝试至少30秒；创建新引擎和CSM解析器，只发一次DETECT，等待车机真实同步。协商期间不把旧CSM当新会话处理，不删除已发送序号伪造ACK，不持续主动发起无限重连。
- 断链时立即停止旧认证计时，避免将中断误记为格式静默。旧轮次排队的iAP2 POST在写锁内检查轮次，旧应答也不能灌入新链路。网络子会话的代数还用于阻止旧的延迟资源重申。
- 对已核对的Mercedes-Benz/MB_D-M-5，必须收到本轮非空挑战应答；全部无响应时不再自发AA05和初始化突发，也不宣称协商完成。这里记录的是收到应答，**没有新增证书链或签名真实性校验**。其他既有兼容策略保留，但同样不能把排队发送当作对端确认。
- 完成回调改为初始化后收到真实NowPlaying/通讯/通话/列表订阅时触发一次。字符串使用NUL结尾；已核对奔驰不再自动发送历史A100/FFFA/FFF0突发。这不实现GPS转发。

独立恢复需要对端配合同步。两次尝试耗尽、对端始终没有同步或仍拒绝认证时，媒体控制功能仍可能不可用；不会据此强拆正在播放的音视频。原始无ACK根因仍需结合新错误上下文确认。

## 2. 封面、媒体订阅和进度

- 手机封面编号改为128–254，按连接分配且不在同一轮重用；耗尽后文字仍继续，封面等待新链路。取消/换图不会接受旧编号的迟到START/SUCCESS。
- 解析0x5000请求字段，只发布支持且被请求的项目，不传未请求的封面。空订阅体保留历史兼容行为；截断、重复或错误嵌套的订阅不改变现有状态。
- 0x5003按SetNowPlayingInformation进度请求记录，明确不声明seek能力；没有把它继续当作封面属性，也未向未验证的播放器盲发seek。
- 接入CarLife 0x10036的protobuf field1毫秒进度，无系统MediaSession时可回退使用；按正式源、曲目切换隔离，限制范围与外推时长。该命令在本车是protobuf，不能照抄参考实现的裸大端整数读取。
- 有界JPEG、文件会话协商、SETUP→START→分块→SUCCESS和媒体内容不入日志的规则保留。图片能否显示在奔驰仪表仍需车辆确认；歌词仍是默认关闭且要求真实歌词源的标题替换实验，没有网易云专用歌词接口。

## 3. 麦克风：双向描述符、一次兼容重试和时钟

只使用车机声明的speechRecognition单声道PCM输入；原有type102媒体输入位为0，不在该流上添加麦克风端口。主音频归车机或已有冲突的type100输出时，不争抢输入。

第一次输入SETUP保留input标志，补PCM的ct、sr、spf，并解析返回的type100描述符/端口。只有已核对奔驰、同一格式同时声明输入与输出、且第一请求返回RTSP400时，才最多重试一次省略input字段的端口式模型。其他拒绝、逻辑错误、取消或换连接不会引发格式轮询。

成功建立双向流且车机返回有效下行端口时，用该流Output密钥发送24k/16k单声道PCM静音RTP时钟及每秒同步包；Input密钥仍独立用于车机上行。时钟只在本次识别租约内运行，不采集手机麦克风、不保存声音，失去主音频/连接或停止识别即关闭。

描述符无效或端口式模型没有返回可用端口时，不启动接收业务；已确认创建的输入按type100/streamConnectionID退役。被拒而未创建的流仍不TEARDOWN。退役未确认时保留登记，阻止再开一条可能冲突的输入；连接结束后清除。保留3秒无认证包退出、30秒识别上限和每次屏幕激活的RECORD去重。

这修复了建流处理缺口，**不证明奔驰已接受请求或小爱已识别**。验收仍分为SETUP200、收到UDP、认证解密、CarLife写入、实际识别外部麦克风五层；本地合成数据回环只覆盖协议处理。

## 4. 源端FPS与分段统计

显示设置的FPS现在传入正式CarLife源，等待车机画布时同时确认FPS上限，最终进入VIDEO_ENCODER_INIT的field3；已初始化的源不因返回主页或重复SETUP再发INIT。仍按VIDEO_INIT_DONE和实际收到的帧统计判断，源端可能不采纳请求。

新增每10秒一行 `CARLIFE-VIDEO:`：输入包数/字节、解析帧数/sourceFps、窗口时长、读入最大间隔、解析最大耗时和回调最大耗时，并列requestedFps/negotiatedFps。没有复制旧帧凑数，也没有无条件增加转码。指标不含画面字节或媒体正文；发送FPS仍不是车机显示FPS。

## 覆盖安装与实车测试顺序

包名com.mcarplay.app，0.1.17-debug/1170000，沿用原调试证书。可覆盖安装，先保留现有蓝牙配对。

1. 先只测试主页/倒车：进入CarPlay，按奔驰原车主页键，再点CarPlay返回，重复3次；倒车临时借屏单独测试。核对0.1.16的永久TAKE/临时借用分流没有回退。
2. 不调用语音，播放网易云、切歌，观察中控原生媒体页和仪表的歌名/封面/进度。导出中核对网络挑战应答、真实订阅、ACK上下文和artworkSetup/Success。网络DEAD时记录恢复尝试和是否出现新同步；不能只看app仍连接或媒体键能用。
3. 再分别长按方向盘语音键、点击CarWith小爱。记录每种SETUP模型及返回码，是否收到认证音频、是否写入CarLife、实际识别了哪里的话音。若仍400，保留该失败，不把“弹出小爱”写为成功。
4. 最后选择60FPS，重新建立会话。分别在连续地图拖动、动画、静态桌面下核对requested/negotiated/source/sent及实际观感。语音前就曾出现低帧率，不能把所有低帧归因于小爱；持续60FPS和最低功耗须分别测量。
5. 每轮只改变一个测试条件，注明动作时间后导出脱敏日志。通知访问可补系统MediaSession回退，但不保证仪表支持封面或原生歌词。

GPS/车辆/仪表导航转发、完整通话、原生歌词、长期稳定性和实际60FPS显示仍未验收。
