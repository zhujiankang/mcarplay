# 0.1.20：资源事务与麦克风信号诊断

以mercedes-carlife的0.1.19为基础。APK为com.mcarplay.app，0.1.20-debug/versionCode1200000；沿用已有调试证书。此次是有明确回归覆盖的候选修复，没有新的奔驰实车测试结果，不能保证已根治语音或Home卡死。

## 已确认的问题与修复

原live changeModes逐项修改归属和语音状态，遇到无效项目直接跳过，始终返回status=0。例如先收到Speech=Recognizing，再遇到无效资源项目，之前的Speech仍可留下，媒体线程会据此停输出。这是代码可证的错误路径，不表示历史奔驰日志中已经发生该非法请求。

现在先校验完整请求，再在隔离候选状态上应用，最后一次性提交；拒绝不改变资源、Speech、revision、屏幕恢复标记和音频事件队列。原RTSP事件应答仍为200，plist status=1且不含成功params；成功为status=0和完整状态。拒绝后不调用SessionController媒体回调，避免继续停流或assertModes。事件连接保持可用。

校验资源/应用ID、转移类型、整数优先级/约束、Speech枚举及Boolean类型，拒绝小数被截断等情况。未知但可安全表示的约束值（如501）继续接受并按禁止抢占处理，不因拒绝车机接管而错误保留手机归属。未知扩展键保留容忍；历史稀疏请求、释放请求重复携带合法约束、字符串/整数borrowID仍可用。/info初始快照继续使用原兼容解析，不把初始声明误当实时请求。

手机向车机发布modesChanged时也修正确认判断：RTSP200但正文损坏、根不是字典或status类型错误，不能再默认为成功并提交手机归属。保留常见空应答/无status字典兼容；明确非零状态仍拒绝。

参考[CatPlay](https://github.com/catplay-labs/catplay/tree/ca30c1365ea9bad931143097079ea388243542f8)的候选状态→整笔提交及错误响应思路，独立实现。没有照搬其严格字段组合校验或改变已有命名借用/永久Home逻辑，也没有引入完整新仲裁模型。CarWith本地录音租约仍覆盖车机Speech，结束后恢复车机状态。

保留0.1.19的停发但保留视频TCP→确认TEARDOWN→关闭socket流程，以及倒车借屏约束、有界恢复与语音串行控制。此次没有根据缺乏实车证据的推断改写SPS/IDR或添加新音频编解码器。

## 麦克风诊断

借鉴DiPlay/OrangeCar中区分协商、首包与信号质量的诊断思路，增加已认证PCM的采样率、接收器启动至首包耗时、总样本数、全零包数、峰值和RMS。全部是累计数字，不保留语音内容；只有认证成功后才计入信号统计。不把全零包等同无连接或识别失败，不因用户静默触发停止。

下一轮可分辨：

- received>0但authenticated=0：需要查密钥、报文格式或认证；不能说麦克风有声。
- authenticated>0、peak/rms持续为0：收到全零PCM，需要查车机录音/资源状态。
- authenticated>0但queueRejected增加：CarLife入口没有接受数据；queued只说明回调接收，不证明已写到CarWith。
- 已有carlifeWritten增加：CarLife socket写出成功；仍需实测小爱是否识别，不能据此宣告ASR成功。

峰值范围0..32768，RMS以累计s16LE样本计算；统计重采样前的认证输入，pcmSamples不是包数。afterReceiverStartMs不等于从按语音按钮到首包的端到端延迟。

## 实车测试顺序

1. 覆盖安装，先保留现有蓝牙配对。播放网易云，原车Home→点CarPlay返回5次，确认原车主页能退出、返回画面/触摸恢复，音乐正常。
2. 倒车进入/退出各3次，检查借屏前归属是否恢复。
3. 点击小爱、长按方向盘语音键，分别说话并等待结束，检查实际识别、音乐恢复及画面。短按原车语音分配不变。
4. 交叉测试语音/Home/倒车；记录动作时间并导出日志，重点对照accepted、MIC信号、carlifeWritten和SCREEN-RETIRE/RECOVERY。

若出现accepted=false，需要结合对应请求结构继续分析兼容差异；不要直接关掉校验或强抢车机资源。尚未实现新的Opus/AAC-ELD输入、GPS/车辆数据/仪表导航或原生歌词；稳定60FPS与长期无断连仍需要实车证据。
