# 0.1.15：CarPToCarL资源申请流程移植

分支 `mercedes-carlife`，基于0.1.14提交 `2a6d8815f5136f505fba56975eb09162285307f2`。参考CarPToCarL1.2.51、commit `3cbc8e85544bcffcc2aa45f1f3c5e1c70f9ca715` 的 `AirPlayResourceState`、`CarPlayAudioIntent` 和 `CarPlayResourceStreams`，适配mcarplay的同机CarLife源、连接代数及奔驰持续视频连接策略。原MIT归属保留，没有打包第三方APK/SDK。

## 从0.1.14扩展了什么

0.1.14主要补奔驰主屏申请；主音频仍有“先改本地归属再发布、未确认仍继续SETUP”的路径，并以单一布尔值记录借用。0.1.15统一了主屏和主音频的申请、借用与归还，按播放意图控制音频生命周期。

| 场景 | 资源与流处理 |
| --- | --- |
| 点CarPlay图标/奔驰新邀请 | 按主屏约束生成申请，等确认且无新事件后提交，恢复新IDR；奔驰复用原屏幕TCP与激活周期。 |
| 倒车/雷达/原车提示重叠借屏 | 每个borrowID独立记录，归还其中一项不释放其他项；高约束未解除时不抢。 |
| 用户播放音乐 | 主音频以用户优先级500申请永久持有，确认后建立音频流。 |
| 原车FM期间导航/TTS | 以后台优先级100临时借用主音频，永久归属仍是车机；播报结束先退役输出流，再确认归还。 |
| 原车接管主音频 | 门控RTP，退役本机输出，暂停本机媒体；重复PCM/旧状态不会立即抢回原车音源。 |
| 车机临时借走主音频后归还 | 只有此前确实因借用被暂停的音乐才恢复；借用期间用户明确暂停则取消自动恢复。 |
| 本机/车机正在语音识别 | 暂停下行音频输出；已建立的输入麦克风与输出流分别管理。车机取得主音频时停止本机输入，遵守其占用。 |
| SETUP/TEARDOWN被拒 | 不虚报成功，不对未创建流发通配拆流；退役未确认时保留描述符，限制重试，再次分配/归还前先清理。 |

## 实现要点与兼容取舍

- `ModeArbiter`成为唯一资源状态来源：永久归属、车机多个临时借用、手机临时借音频分开保存。具名借用重发幂等，同ID更严格的约束生效；匿名借用按栈归还。未知具名归还不会释放其他借用。旧接收端省略归还ID时，仅在恰有一个未还借用时使用兼容回退；多个借用时不猜。
- `/info`初始化清除上轮借用和本机识别态，兼容永久归属快照。车机appStates独立保留，本机识别结束后恢复车机原语音态，而非一律写成无语音。
- 主屏、主音频申请和手机临时归还共用“拟申请快照→发布→确认→按版本提交”。发布不持仲裁锁，等待网络时事件读取线程仍能处理新的倒车/通话请求；新事件优先，旧申请不能覆盖它。
- 所有requestUI使用确认式申请；奔驰ctrl邀请仍不允许结束倒车借用。其他车机保留原有返回策略入口。奔驰不因借屏重新屏幕SETUP/RECORD。
- 资源协调、音频起停与屏幕操作使用同一串行控制工作线程。播放变化只登记意图并合并通知；正式源有效期间有250ms收敛任务，源退役时停止。申请/起流/退役重试有2秒间隔，防止PCM频繁触发请求。
- 格式初始化不是实际播放证据：初始音乐意图以已读媒体会话/真实PCM为准。连接不再无条件预占空音频，`audioFirst`旧启动实验不再强制提前分配无播放意图的流。
- CarWith原生MEDIA/TTS/VOICE事件接入意图与PCM门控。媒体按播放意图放行，提示在独立、有上限的短缓存中等待建流：32块/256KiB/最长1500ms，不保存到磁盘；超过等待窗口可能丢弃提示开头，不能宣称所有慢建流都无截断。
- RTP发送端检查最新归属/识别态，既门控新PCM也门控已经排队的包及补静音包。媒体键的明确播放/暂停会更新意图；系统媒体键派发不保证每个内置播放器都执行，因此实车仍需确认暂停/恢复。
- 输出流只记录成功创建的type/streamConnectionID；音频退役只拆这些描述符，不拆主屏、整轮会话或麦克风输入。旧连接、旧源、旧协调器不得改动新轮次。
- 输入麦克风允许在没有媒体输出时单独协商；仍避开与已有type100输出的冲突。0.1.14端口/拒绝清理及0.1.13媒体信息/封面修复保留。

## 新诊断

- `RESOURCE-SCREEN: 取回主屏 ... acquired=...`：确认式主屏申请结果，不能代替仪表/中控的实际出画。
- `RESOURCE-AUDIO: acquire media=... prompt=... temporary=... accepted=...`：音频意图和资源申请结果，不能代替实际出声。
- `RESOURCE-AUDIO: output stopped teardownAccepted=...`：输出已经停止，及退役确认状态；保留屏幕/控制/独立输入。
- `RESOURCE-AUDIO: releaseTemporary accepted=...`：临时音频归还结果；永久归属应恢复原车。
- 继续分别查看MIC的SETUP、认证包、CarLife写入与小爱实际识别；资源移植不代表麦克风已实车识别。

已缓存提示回放时按缓存时长延长借用排空窗口，普通新包不缩短该窗口，避免归还音源时切断仍在回放的提示。音频流注册、音量查询与退役都使用原连接代数；RTSP200内的非零逻辑状态仍视为退役失败，不遗忘待清理的描述符。

这些日志不含歌曲、歌词、原始PCM或borrowID正文。没有新增自动上传。

## 安装与验收顺序

1. 覆盖安装同证书0.1.15-debug/1150000，先保留既有蓝牙配对；记录手机、CarWith/CarLife版本、车型与固件。
2. 先不播放音乐，连接CarPlay，确认画面/触摸；暂时没有音频流属于按需行为，不等于音频故障。
3. 播放、暂停、再播放音乐，检查申请确认、实际出声及起停；切到原车FM后确认本机音乐不会自行抢回音源，用户明确再按播放应能申请回来。
4. 若车机允许原车音源期间运行CarWith导航，测试提示临时借用、提示结束归还、原车音源恢复。记录是否丢开头、延迟或残留音频。
5. 驻车且环境安全时测试倒车/雷达借屏和归还，重复3次；不抢倒车画面，奔驰屏幕流不应因资源切换重复SETUP/RECORD。正常手动切换原车主页、点击CarPlay返回也单独测试。
6. 再分别长按方向盘语音键与触摸小爱，记录画面/触摸/声音是否仍有响应，麦克风是否实际识别。借用归还后不应自动播放原先就暂停的音乐。
7. 导出脱敏报告，注明每个动作与异常时间。若仍有虚拟iAP2 packet105未确认，保留该独立问题，不把它标为资源流程已修复。

本版没有新实车证据；用户上一轮报告实际为0.1.12。GPS/车辆数据/仪表导航转发、完整通话接入、持续60FPS与不间断连接均不由此次移植自动成立。
