# 奔驰 CarLife 测试包 0.1.8

分支：`mercedes-carlife`。基线为 0.1.7 / `3ef5987`；本轮仍走同机 CarWith → CarLife → 无线 CarPlay。没有引入 ICCOA 或有线 USB CarPlay。

## 修复内容

- DETECT/marker 改为链路层增量解析，校验完整标记。首条探测单次回显，重复探测才升级 SYN；半包/粘包输出与单独消息一致。没有把阈值简单降为 1，也不挂首条回应的无限重发。
- 蓝牙向 Wi-Fi 交接以本轮已确认的 SETUP/活跃控制连接作保护；不再把已建立网络会话、尚未启动视频的窗口直接取消。该保护不等于网络 iAP 认证完成。
- 端点、客户端和视频发送器按本轮代次认领；迟到的旧蓝牙、事件通道和媒体回调不能取消/接管新轮。用户停止优先，新端点不会复活已停止的用户意图。
- 事件通道 EOF/reset 或媒体发送结束进入统一资源退役，停止旧 AirPlay 心跳、CarLife 和音频资源。仅主屏借用/主动替换发送器不走整会话失败处理；视频数据口单向 EOF 本身不被直接当作整会话失败。
- 已取得车机网络端点后，在 AirPlay 配对阶段准备本机 CarLife，提前完成源端入口/握手。仅保留最近可解码 GOP，最多 48 帧/6MiB；超限、参数集变化、源退出后清空，等待新 IDR。RECORD 确认后才提交到车机，不重用不同源的参考帧。
- 用户选择的声音模式持久保存。自动连接/回连尊重该选择，源可用性不再把“无声”覆盖成“开启声音”。
- 正常停止 CarLife 的诊断显示 `code=NONE`；失败仍保留实际错误。删除未经本车验证的“约 10 秒看门狗”断言。

## 奔驰实验启动策略

「车机显示」新增“奔驰启动方式（实验）”。只匹配 `/info` 或蓝牙信息中的 `manufacturer=Mercedes-Benz` 且 `model=MB_D-M-5`；不对所有车机强制同一时序。设置在下一条新连接生效，已开始的 RECORD 结果不会被中途重置。

| 方式 | 处理 |
| --- | --- |
| 一次激活（默认） | 视频 RECORD 优先，音频后加入，但不重复发第二次 RECORD |
| 原顺序 | 保留 0.1.7 的视频 RECORD → 音频 SETUP → 后补 RECORD，便于对照 |
| 声音优先，一次激活 | 先连接视频数据端口，再音频 SETUP，最后一次 RECORD |

默认“一次激活”是针对日志中重复 RECORD 后快速关闭的候选策略，**尚未实车证实为奔驰正确顺序**。不能据此宣布已适配。它继续使用 mcarplay 的共享请求结果/代次检查：请求超时或被拒不能在重复调用时伪装成成功。

`family=GENERIC` 与 `STARTUP: mode=SINGLE_RECORD` 可以同时出现；基础协议分类与本轮实验策略是两个独立信息，不表示误识别车型。

## 测试方法

1. 覆盖安装 `0.1.8-debug`，包名仍为 `com.mcarplay.app`。使用与上一版相同的本地 debug 证书；若手机上的 0.1.7 正是前次交付包，可保留数据升级。无需为这次更新重新删除已经能识别 CarPlay 的蓝牙配对。
2. 打开应用，保留提前发布能力开关。明确选择奔驰为目标，避免探测耳机。首次先用默认“一次激活”连接；观察至少 30 秒，确认车机实际出现可操作 CarWith 画面。
3. 注意：CarWith 入口现在可能比上一版更早出现，这是源端准备时机调整；页面出现不等于持续输出。检查 `CARLIFE-PREWARM`、`STARTUP`、首次 DETECT 回应、网络链路 NORMAL、持续视频帧、原生音频及触控。
4. 如果仍快速断开，先手动断开，再仅将声音选择为关闭测试纯视频，其他项不变。选择会保留，自动回连也应尊重它。
5. 需要对比启动顺序时，每轮手动断开后只改变“奔驰启动方式”，保留 CarLife/CarWith 版本及其他参数。不要在同一轮同时更换组件版本、分辨率和认证策略。
6. 每轮记录车机界面、是否有画面/声音/可触控、选定策略和手机操作，再导出脱敏报告。没有实际显示证据时，“发送帧数”只说明本机写入，不代表奔驰已解码。
