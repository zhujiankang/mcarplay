## 问题一：语音事件的字段解析错误

**18:19:08.253（行5300）**收到真实事件 `requestSiri params.siriAction=1`。退出汇总（行5404）记录该轮4条 requestSiri、解析失败0条，但 0.1.11 业务分支只读取 `params.action` 或顶层 `action`，漏读标准 `params.siriAction`。因此事件层虽成功收到请求，业务层没有执行语音按键转发，也没有产生预期的 `VOICE:` 动作日志。这是确定的代码错误。

只有首条 requestSiri 打印字段形状，不能据此断言其余3条全是预热、按下或释放。

修复内容：

- 优先解析标准 `params.siriAction`，兼容历史 action/顶层字段和整数文本，拒绝无效、非整数或不支持的枚举；二进制 plist 回放验证真实字段类型。
- 每次记录 `PREWARM(1)`、`BUTTON_DOWN(2)`、`BUTTON_UP(3)`；实际转发继续记录 `VOICE: steering key=... carlifeSent=...`。
- 保留按键去重、短按释放不立即结束识别、长按释放按 PTT 结束。已核对奔驰身份保留短时间 prewarm+release 无 down 的兼容。
- 单独 PREWARM 不当作用户已选择手机语音，避免与原车语音同时抢麦。如果短按仅触发奔驰本地语音或只传预热，本应用不能保证重新分配原车按键。需分别测试短按、长按；不能用 App 强行抢占奔驰高优先级语音资源作为修复。

用户反馈点击 CarWith 小爱图标可以立即拉起，支持“源端入口可用”的判断；不等于车机麦克风已回传。该轮只有唤醒词收音请求日志，没有确认显式识别输入启动，最终 `carlifeWritten=0`。本轮没有车机采音或小爱识别成功证据。

## 问题二：接管主屏后不必要地拆流、再次激活

关键时序：

| 本地时间 | 事件 |
| --- | --- |
| 18:19:31.156 | 奔驰报告主屏由车机借用，约束500。与用户报告的倒车接管时间吻合；协议字段本身没有明确写“倒挡”。 |
| 18:19:31.169–.180（行5380–5385） | mcarplay 停止原视频发送端，并向车机发送屏幕 TEARDOWN，车机回200。 |
| 18:19:31.981–18:19:33.207 | type102音频反馈继续、CarWith视频源继续。不是整个手机源已先行崩溃。 |
| 18:19:34.456 | 奔驰归还主屏。 |
| 18:19:34.467–.487（行5394–5400） | mcarplay 新建屏幕 SETUP、数据口及 RECORD。 |

| 18:19:41.197 | 用户手动取消并关闭蓝牙/Wi-Fi监听。自动启动之后还受原有30秒手动停止冷却约束；这项限制不等于手动点击启动必然无效。 |

日志直接暴露了“临时屏幕接管被处理成视频流退役与重新激活”的问题。它不能单独证明奔驰内部究竟因第二次激活、重建时序还是新流没有及时首帧而退出，因而不宣称获得了 MBUX 内部拒绝原因。

修复策略只对已核对身份 **Mercedes-Benz/MB_D-M-5** 生效：

1. 原车/倒车界面取得主屏时，保留原视频 TCP、加密序号及激活周期；CarWith源、音频、事件通道和心跳继续。只暂停图像，不发送屏幕 TEARDOWN。
2. 按实时主屏归属门控视频与触摸，遵守车机约束，不强抢倒车画面。即使接管时间很短、期间没有源视频帧，也记住暂停状态。
3. 车机归还后请求新 IDR、重新发送参数集，从新 IDR 恢复图像；不进行接管引发的第二次屏幕 SETUP/RECORD。
4. 原车主页返回同样保留这条连接，旧的 requestUI“需要重建”标记不再触发奔驰的屏幕拆流。其他接收端保留原有生命周期策略。
5. 旧会话/连接代数变化后的回调不能恢复新会话；真实的控制/媒体断开仍按终态处理，保留手动停止的语义。

这修复了当前代码触发的退役路径，不是对“奔驰将永远保持视频 socket”或“所有断线都会立即自动恢复”的保证。接收端如果在接管期间主动关闭旧流，仍需根据新日志继续定位，不靠向倒车画面强送视频回避。

## 新 APK 测试顺序

1. 覆盖安装同证书0.1.12-debug，先保留蓝牙配对，使用最近能够出画的连接流程。
2. 稳定出画后分别测试方向盘短按和长按。确认 `VOICE: requestSiri siriAction=...`、`VOICE: steering key ... carlifeSent=true`；仅有 PREWARM 或启动奔驰本地语音时不要判定小爱链路成功。再点 CarWith 内小爱作对照。
3. 在安全停车环境测试一次倒车接管/归还，再重复3–5轮；对比原车主页返回。记录是否有正常原车画面、归还后恢复CarWith、音乐和触控是否继续。
4. 新日志应出现 `SCREEN: 奔驰接管主屏——保留视频连接...` 与 `SCREEN: 奔驰归还主屏——复用原视频连接...无 SETUP/RECORD`，随后有 `VIDEO: 主屏输出恢复——首个 IDR 已放行`。接管期间的暂停计数不是视频断线。
5. 如仍退出，立即导出诊断并记录接管、归还、短/长按的时间。先保留首次失败日志，不必立即删除配对。若主动点了断开，标记该操作，避免把用户停止后的自动连接冷却混入系统故障。
