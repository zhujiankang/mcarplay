## Home 返回后重新进入

报告 54a35fe5 在首帧后记录 app-only Wi-Fi Network 138 丢失，随后已有视频及控制仍能工作。原实现清除进程网络绑定，却没有恢复已连接车机网络；下一次打开屏幕 TCP 存在走默认网络的风险。这是代码可修复的缺陷，但报告没有完整 Home/requestUI/崩溃栈窗口，不能把它说成此次“崩溃”的已证实唯一根因。

本版在活动会话网络丢失后，被动观察并重新绑定已经连接、SSID 匹配的车机 Wi-Fi，不重新发起热点切换或系统选择框。保留原 network request，避免解除请求本身导致物理网络断开；新旧 observer 按所有者及连接代次隔离。每轮最多三次，间隔 1.5 秒，耗尽后至少冷却 5 秒且仅明确操作可重开预算。用户停止、旧连接迟到结果不能恢复新会话。

屏幕返回先等待网络重新绑定，再走原有资源申请与屏幕恢复，避免直接在默认网络上新建 SETUP。如果系统隐藏 SSID，仅接受同一此前已验证的 Network；隐藏 SSID 且网络标识已改变时不会盲绑。此情况下仍可能需要补充系统网络权限或连接操作，不能承诺所有断网均自行恢复。

本轮日志已有 RTSP 200、24kHz 认证输入、302 个有效且非全零数据包，并有至少一次 CarLife 16kHz 写出；不能继续归为旧版输入 SETUP 被拒，也不能因写出一次就认定 CarWith 收到了整段语音。约三秒录音不足以触发原每 250 块一次的周期摘要。
