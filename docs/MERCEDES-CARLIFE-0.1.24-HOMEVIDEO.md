# 0.1.24-homevideo：让屏但持续发送视频的独立实验

日期：2026-11-19。基线：mercedes-carlife / 0.1.23 / 1586b5816042496890d716290a67a74ad2068902。

## 安装包与构建隔离

实验包：com.mcarplay.app，0.1.24-homevideo-debug，versionCode 1240001，沿用先前调试证书，可覆盖安装。它是独立的策略测试包，使用原包名避免蓝牙身份、授权和本地 CarLife 通道改变，不与普通版同时运行。普通构建默认关闭实验，为 0.1.24-debug / 1240000。实验未写入持久化设置，后续普通包不会继承“继续发帧”开关。

构建命令：

```sh
./gradlew -Pmcarplay.mercedesHomeVideoTest=true :app:assembleStandardDebug
```

开关仅对 debug 生效，拒绝组合 release 任务、release tag 或签名构建号。实验只匹配既有已核对身份 Mercedes-Benz / MB_D-M-5；其他接收端保留原策略。版本号比 0.1.23 高，若要回装更低 versionCode，系统安装器可能拒绝降级；不建议为回退卸载清数据。后续更高版本正常覆盖即可。

## 本次唯一变量

原 0.1.23 永久让屏：暂停视频 → 确认屏幕 TEARDOWN → 关闭视频 TCP；重新进入时重新建视频流。

实验包：

1. 原车通过资源消息永久取得主屏时，真实归属照常提交，不主动申请抢回屏幕，也不向 CarWith 转发投屏触摸。
2. 保留原视频 TCP、流标识与加密计数，源端继续工作并发送实际图像及原有 keepAlive；不因这次让屏发送视频 TEARDOWN。
3. 用户再次点击 CarPlay，收到有效 requestUI/邀请并确认取回资源后，复用原视频流。持续流不会因这次界面切换重置加密 nonce，也不额外 SETUP/RECORD；可以按原机制请求关键帧。
4. 临时借屏仍停图像、保留视频连接，归还后从新 IDR 恢复。从原车 Home 进入倒车时，即使可见性始终是“车机持有”，也会识别借屏状态变化并暂停；退出倒车回到 Home 后恢复隐藏视频传输，不擅自显示 CarPlay。
5. 明确停止、真实视频 EOF、控制关闭、用户断开和连接代次变化仍走清理/原有有界恢复，不把已经失效的视频 socket 当作可复用。

保留 0.1.23 的首次蓝牙服务端及客户端、Wi-Fi 有界重绑定、麦克风和资源事务。没有合入 CarPToCarL 后台保活、非阻塞音频或采样率改动。本包用于验证持续图像是否影响奔驰的视频空闲/再进入，不承诺解决全部 Home 故障。

## 代码与本地验证

资源归属和传输许可分开：ModeArbiter 仍返回真实屏幕归属；实验许可只传入 VideoSender 与屏幕流协调器。接收端身份、构建开关、临时借屏及旧会话共同约束许可。

本地完整门禁通过：standard 1125 项、remote bridge 24 项，均 0 失败/错误/跳过；定向 68 项通过，新增 9 项回归。Spotless、standard lint（0错误）、实验 debug 构建和同证书检查通过。真实加密 TCP 回环检查 Home 期间继续传帧、相机覆盖时暂停、返回 Home 仍无显示权、再次进入复用 TCP，并按连续 nonce 成功解密。回环中的 90 秒时间推进使用模拟时钟，不代表运行过奔驰 90 秒看门狗，更不等于实车通过。

## 实车测试顺序

1. 覆盖安装，确认版本为 0.1.24-homevideo-debug。先保留已有蓝牙配对，按之前能成功的方式进入 CarWith。日志应有 HOME-VIDEO test build 与 receiverMatched=true；未命中时不能当作此实验已经运行。
2. 先不开小爱。点击奔驰原车 Home，停留至少 90 秒。观察原车主页能否操作、音乐/切歌是否正常；隐藏视频 FPS 非零是实验预期，不代表原车屏幕被抢占。
3. 点击原车顶部 CarPlay，确认画面与触摸恢复。重复 5 轮，至少包含短停留和超过 60 秒停留。记录每次 Home 与 CarPlay 的时间，不能只看 App 显示“已连接”。
4. 再测试 CarPlay → 倒车 → CarPlay，以及 Home → 倒车 → Home → 点击 CarPlay。倒车期间应暂停图像；返回 Home 后可以后台送帧，但不能自行跳回 CarPlay。
5. 前四步通过后再单独测小爱。麦克风识别并非本轮修复目标；出现故障应记录触发时间，不与 Home 的第一轮基线混在一起。
6. 导出完整诊断。优先检查 HOME-VIDEO hidden frame written 的同一 stream 标识是否持续、是否出现 SCREEN-RETIRE/新 SETUP/RECORD、Wi-Fi lost、视频/控制 EOF，以及点击后资源是否真正回到手机。

如果原车主页可操作、持续送帧且再进入正常，才支持当前实验方向。若再次进入仍失败，应沿完整资源交接/车机解码与控制通道继续查，不将持续发送当作已证实修复。后台持续传输可能比停图像更耗电，本版不宣称节能或稳定 60FPS。
