# 奔驰异常断线后回连修复测试包 0.1.10

分支：`mercedes-carlife`；基线为 `319db11` / 0.1.9。仍走同机 CarWith → CarLife → 无线 CarPlay。

## 已修复的范围

0.1.9 异常媒体结束时设置了全局取消标志，虽然保留蓝牙服务监听，新的车机回连仍会被业务层立即拒绝。用户日志中 12:57:22 的“接收 IAP2 → 立即 LINK closed”与该路径一致。

0.1.10 只在仍有运行中的蓝牙监听/客户端、没有用户停止、没有正在清理或其他会话启动时，允许真正的新回连开始新诊断周期并清除旧媒体周期的取消状态。端点代数递增，旧回调继续隔离；手动停止和清理期间仍拒绝连入。新增 `BT-INCOMING` 明确记录业务准入原因，避免把接受蓝牙 socket 当作协议已成功。

0.1.9 的原生尺寸申请、比例适配与主屏资源生命周期保留。此次没有修改 SDP UUID、没有增加录音权限请求，也没有实现麦克风上行。

## 本次实车证据与限制

手机 Xiaomi 24129PN74C、Android16/API36；CarWith 4.0.9-20260629、CarLife8.8.5；用户报告奔驰 GLC2602024，接收端 MB_D-M-5，完整固件未知。

用户确认 0.1.9 首次连接画面和音频正常；本轮请求、VIDEO_INIT_DONE 和实际 SPS 均为 1624×1150。点击 CarWith 内小爱后提示麦克风异常，随后卡住并退出。日志在 12:57:16 记录约18秒多通道停顿后的 UDP EPERM、屏幕/事件/控制连接关闭；没有这次的新 native 崩溃证据。10:51:30 的 native SIGSEGV 是历史记录。

这次有一个明确的自动回连准入缺陷，但后续人工重试已重新发布三个 SDP 服务，却没有新的车机 iAP2 连入。因此该修复**不能保证**奔驰 CarPlay 图标立即恢复。系统停顿/网络 EPERM 和网络 iAP2 ACK 失败仍待定位。

用户不确定故障前后手机是否锁屏或后台。日志有电池优化未豁免记录，但最后一次亮屏状态不等于故障瞬间状态，不能把省电策略直接定为根因。

## 麦克风与语音

当前支持的声音方向是 CarWith/CarLife → 奔驰扬声器。完整车机麦克风链路还需要 CarPlay 输入流、接收解密/格式转换以及 CarLife/CarWith 可接受的录音入口，0.1.10 没有实现。

导出时 CarWith 录音权限已授予，CarLife+ 和 mcarplay 的录音权限未授予。CarLife+ 若尝试使用手机麦克风，需要另查该应用的权限与实际采集进程；仅授予 mcarplay 录音权限不会自动建立尚未实现的中继。

本轮先避免调用小爱，验证正常音视频和断线恢复，不能将本包标为语音助手可用。

## 安装与测试

包名 `com.mcarplay.app`，版本 `0.1.10-debug` / `1100000`，签名保持原 debug 证书，可覆盖安装，无需因更新再次删除配对。

1. 驻车，允许 mcarplay 后台运行、电池“不限制”，保持亮屏与应用可见，不划掉最近任务；这用于排除干扰，不是已经验证的根因修复。
2. 若奔驰仍无 CarPlay 图标，先按该车型支持的方法重启 MBUX，或等待车辆完全休眠后唤醒。打开 mcarplay 并启动连接，再在奔驰设备管理中连接手机，不反复删除蓝牙配对。
3. 先不触发语音助手，验证 1624×1150 画面、声音和触摸，并记录时间。
4. 若出现自然异常断线，让奔驰再次尝试回连，观察是否出现 `BT-INCOMING: ACCEPT reason=RECOVER_RETIRED_MEDIA_SESSION`。它只证明新的业务准入，后续还需看到 iAP2、Wi-Fi、AirPlay、真实新帧。
5. 手动停止后应不再自动恢复；保留新诊断用于核对准入、实际握手和首次视频。

若仍无图标，可用故障后的 iPhone 无线 CarPlay 作对照：iPhone 也失败时优先检查车机当前无线投屏状态；iPhone 正常而本机失败时重点看手机能力发现/iAP2 识别。该对照不要求删除其他设备记录。

新增5项回归；完整 standard 958 项、remote bridge 24 项均为0失败/错误/跳过，lint/debug构建和同证书签名校验通过。格式校验与完整文件摘要见交付清单；0.1.10 未经奔驰实车验证。
