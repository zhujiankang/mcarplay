# 0.1.18：屏幕局部恢复与语音资源协调

日期：2026-11-17。基于 `mercedes-carlife` 0.1.17（`29b3c3b`）。本轮只有代码和回环验证，没有新增奔驰实车证据。

## 资料范围与实现选择

Apple 的 [Developing CarPlay Systems, Part 1](https://developer.apple.com/videos/play/wwdc2016/722/) 说明退出 CarPlay 画面仍可保留会话、音乐、位置和媒体信息；[Part 2](https://developer.apple.com/videos/play/wwdc2016/723/) 说明 mainScreen/mainAudio 独立仲裁、TAKE/BORROW/UNBORROW、changeModes/modesChanged 与 Speech appState。用户提供的《CarPlay Developer Guide》2026-10-13 版，页脚27/30/52–55说明语音音频按需占用、导航播报混音和仪表地图独立场景。它是 iOS 应用层指南，不能把 Scene 断开当作整车连接断开；没有规定本实现必须保留或重建视频 TCP。

延续0.1.16奔驰临时借屏保留原视频连接、永久Home退役主屏的策略；这仍是待实车验证的兼容策略，不称为Apple底层规范。只读取和引用资料，没有导入第三方SDK或复制外部实现代码。

## 主屏修复

- 奔驰 ctrl 邀请以已安装的屏幕生命周期和有效控制连接为前提，不再依赖 videoSender 正在运行。Home退役后仍能进入恢复检查；邀请本身不解除倒车借用、NEVER或高优先级约束，也不冒充明确requestUI。
- ATTACHED/HIDDEN/DETACHED/RETIRE_PENDING/RESTORE_PENDING/EXHAUSTED/CLOSED明确区分。局部失败最多3次，每次间隔至少2.5秒，由同一串行控制线程推进；耗尽保留控制/音频，等待冷却后的明确requestUI开启新预算。普通重复邀请不刷新预算。
- 旧屏幕流必须确认退役才可新建。SETUP超时或成功但描述符坏时保留原uuid/connectionID用于定向退役；RTSP拒绝不视作已创建流。TEARDOWN还检查plist逻辑status。视频SETUP后的数据端口/RECORD失败同样先清理再重试。
- 已运行视频通道意外结束，先按当前发送器和连接身份转入局部恢复；旧发送器迟到回调不影响新发送器。初始连接尚未安装屏幕生命周期或控制真正结束时仍走完整清理。
- CarWith画面内返回车机只让出主屏，不再擅自让出音乐。奔驰实际发送的mainAudio切换仍正常仲裁。临时借屏归还只恢复之前归属，不保证返回CarPlay。

## 语音修复

- 正式会话的麦克风协商和音频/屏幕资源任务使用同一控制工作线程；事件读取、媒体读取、音频数据发送和独立语音超时仍不在该线程等待网络。
- CarWith请求录音时，若音频归原车，先按用户优先级申请临时主音频；受约束拒绝时不强抢。准备语音时先暂停并确认退役旧媒体输出，再建立语音输入，避免type100相互覆盖。
- 麦克风输入与双向语音下行保留原能力校验。对已协商并返回有效输出端口的双向PCM语音流，把CarLife VOICE(9242)声音转换为该流声明的16k/24k单声道；空闲继续20ms静音时钟。队列最多300ms，新初始化/结束清空，不回放旧声音，不采集或保存手机麦克风。
- 停止、取消、无认证包或超时关闭输入；先定向处理输入退役，再清除Speech状态、归还本次语音新借的音频并重新协调媒体。原已归手机/原已借用的音频不会被本次语音随意归还。
- 没有车机PCM输入能力、没有双向下行端口、麦克风仍返回400、输入退役未确认等情况仍可能不可用；不猜测Opus/AAC-ELD格式，也不将本地回环当作小爱实车识别成功。导航TTS仍沿用当前提示混音/缓冲；本轮没有完整新增独立alternateAudio传输。

## 安装与实车验收

候选0.1.18-debug，包名com.mcarplay.app，沿用调试证书；可覆盖安装，先保留原蓝牙配对。

1. 不开小爱，播放网易云。奔驰原车主页→CarPlay重复5次，确认原车按键可用、音乐继续、再次进入出新画面。
2. 分别从CarPlay画面和原车主页进入倒车，再退出倒车。核对恢复到之前画面；倒车期间普通ctrl邀请不能抢回屏幕。重复3次。
3. 点击小爱/长按方向盘各3次，记录是否听到提示、车载麦克风能否被识别、结束后音乐与触摸是否恢复。短按的奔驰原生语音分配不由手机强制改写。
4. 语音期间回主页、倒车，随后再进入CarPlay。确认无循环重建；若达到屏幕重试预算，等待冷却后再次明确点CarPlay。
5. 每项注明动作时间并导出脱敏报告。区分CarLife源FPS、发送FPS和车机实际显示；隐藏期间发送0FPS可以正常。

## 验证状态与限制

完整门禁通过：standard1075项、remote bridge24项，均0失败/错误/跳过；Spotless、standard lint（0错误）、standard debug构建通过。调试证书SHA256保持 `cf224300d4bde33160f08559301026f393c2916ea8131eaad8adefad0fd7b266`，APK版本0.1.18-debug/versionCode1180000。相对0.1.17新增14项测试。新增回归覆盖缺失发送器的真实邀请入口、退役未确认、恢复预算、控制更替、语音临时音频归还和PCM下行。单元/回环不能证明GLC实车通过。

仪表封面、原生歌词、GPS/车辆数据、仪表地图、完整通话、长时稳定性和实际60FPS未在本轮实现或验收。指南页脚5要求CarPlay音频应用不展示歌词，不能把原生仪表无歌词直接认作桥接失败；封面单独验收。仪表地图需要独立能力和源数据，中控H.264不会自动变成仪表地图。
