# 奔驰 CarLife 测试包 0.1.9

分支：`mercedes-carlife`，基线 `504fdee` / 0.1.8。同机 CarWith → CarLife → 无线 CarPlay。

## 本轮修复

- 参考 CarPToCarL 1.2.51（`3cbc8e8`）的资源应答和屏幕流管理，在事件请求原应答中返回 `status` 与当前资源参数；事件线程只做内存仲裁，耗时 RTSP 操作在控制工作线程串行执行。
- 奔驰接管屏幕时停止并 TEARDOWN **屏幕流**，保留 CarWith 源、控制连接和原有音频。资源归还或允许的 `requestUI` 到来后重新 SETUP/RECORD，重发视频配置并等待新 IDR。原车界面期间的缓存不回放到恢复后的画面。
- 屏幕暂停仍属于已连接，不再因 `videoSender=null` 被当作失败启动或再次进入蓝牙连接。暂停期间的冗余 Wi-Fi 凭据不会重新绑定网络。
- 奔驰单次 RECORD 限制以每次屏幕 SETUP 激活周期为范围：追加音频不重复激活，重建屏幕后允许一次新 RECORD；旧周期迟到响应不能激活新屏幕。
- 预热可以提前打开源端入口并握手，但正式视频 INIT 等待车机画布到达。更新已运行但尚未初始化的源，避免固定为 1280×720；不通过重复 INIT 热切换已有源会话。
- HU_INFO 携带申请画布，特征保留 `CONTENT_ENCRYPTION=1` 并增加 `DISABLE_RESOLUTION_OPTION=1`，请求源按车机尺寸编码。返回格式和实际 SPS 仍作为源尺寸依据。
- 正式桥接中，源/车机比例差超过 1% 时自动尝试一次硬件转码并等比例留边；同比例的不同分辨率继续透传。转码失败会记录并回退透传，因此不能保证所有设备上均消除比例问题。
- 留边与触摸使用同一内容区域，触摸输出使用声明给 CarLife 的显示坐标域；黑边不转发触摸，并释放已有手势。原生尺寸一致时没有这层转码开销。

## 手动分辨率与自动适配

你可以先将手机 CarLife 的屏幕分辨率手动设成 **1624×1150**。请在停止本轮连接后修改，下一轮连接生效。新版也会自动读取奔驰 `/info` 画布；这辆车前次报告就是 1624×1150。

自动适配不修改 CarWith/CarLife 应用的持久设置，也不要求 root。它通过本次协议协商申请分辨率，源端是否采用由 CarWith 决定。

| 实际返回 | 新版处理 |
|---|---|
| 1624×1150 | 原生比例透传，无需比例转码 |
| 同比例的其他尺寸 | 继续透传，不只因像素数不同强制转码 |
| 1920×1080 / 1280×720 | 自动尝试等比例留边转码；1624×1150 中内容区域约为 1624×914，上下约 118 像素留边 |
| 无法初始化硬件转码 | 日志明确记录失败并回退透传；优先用手动原生分辨率再测 |

保留整个 16:9 内容就会有留边。要完整铺满 1624×1150 且保持比例，需要 CarWith 原生采用该画布重新排版。只改宽高标签不能实现。

转码会增加处理开销，实际延迟、功耗、温度与奔驰解码兼容性需要实测；本轮没有性能测量结果。建议第一轮把 mcarplay 目标帧率固定为 30、缩放固定为 100%，其他实验设置保持上次成功出画的值。

## 覆盖安装与测试

APK 使用与 0.1.8 相同的 debug 签名，包名保持 `com.mcarplay.app`。直接覆盖安装；保留手机和奔驰现有蓝牙配对、CarPlay 记录，正常情况下无需删除重配。

驻车测试，先专门验证返回流程：

1. 停止旧连接，设置手动分辨率 1624×1150，覆盖安装新版。
2. 正常进入 CarPlay，确认 CarWith 出画、比例、触摸与声音，记下首次出画时间。
3. 点击**奔驰原车触摸 Home/返回键**，确认真正显示原车桌面，而非只停在 CarWith 最后一帧。
4. 从奔驰菜单再次进入 CarPlay，确认出现新画面、触摸可用；重复至少三轮。不要在中途重启 CarWith，以便验证同一源会话恢复。
5. 导出本轮诊断，并记录每次按键的时间。区分“原车界面期间正常暂停”与“再次进入后仍没有新帧”。

第二轮可把源端分辨率恢复默认，单独验证自动适配：检查请求尺寸、VIDEO_INIT_DONE/SPS、是否触发等比例转码、实际比例和黑边区域触摸。不要把两轮同时改变多项设置。

重点日志：

```text
CARLIFE: 自动适配车机画布 1624x1150
CARLIFE: 请求编码尺寸 1624x1150
CARLIFE: VIDEO_INIT_DONE ...
EVENT: changeModes 原请求应答（主屏=车机...）
SCREEN: 让出主屏——退役屏幕流...
AIRPLAY: TEARDOWN（屏幕流）[RTSP/1.0 200 ...]
SCREEN: 主屏流已重新 SETUP/RECORD...
```

这些日志分别证明协议步骤，不单独证明车机 HMI 已切屏或实际播放。画面和声音仍需你观察确认。

## 验证边界

新增 20 项回归测试，覆盖实际 TCP 事件应答、奔驰屏幕重建激活、迟到 RECORD 隔离、资源接管/借用归还、预热尺寸时序和触摸几何。完整 standard 953 项、remote bridge 24 项均为 0 失败、0 错误、0 跳过；Spotless、standard lint/debug APK 构建通过。APK 已通过签名校验，证书与交付的 0.1.8 一致，版本为 `0.1.9-debug` / `1090000`。完整校验与文件摘要随交付清单记录。

0.1.8 实车已经有用户确认出画，但同一日志还记录 native 崩溃和网络 iAP2 ACK 失败。**本轮没有定位并消除这两个独立问题**，也没有完成 0.1.9 奔驰实车验收。若再次崩溃或 iAP2 DEAD，请保留新日志；不要把屏幕切换改动视为整条链路已稳定。
